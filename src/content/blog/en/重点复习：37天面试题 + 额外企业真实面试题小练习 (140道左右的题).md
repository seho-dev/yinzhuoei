## What Is the Difference Between link and @import When Adding Styles to a Page?

First, one is an HTML tag, while the other is CSS syntax.
Compatibility: link works in all browsers; import is CSS3 syntax supported only by modern browsers.
Loading order: CSS added with link loads as the document loads, while @import loads styles when the CSS is processed.
Control: JavaScript can change which CSS a link loads, but it cannot do the same with @import because it is CSS syntax.

## Understanding the Holy Grail and Double-Wing Layouts: How Do They Differ?

Both the Holy Grail layout and the double-wing layout solve the same problem: two fixed-width sidebars with a fluid center column that renders first. To make the center flexible and prioritize its rendering, its DOM element must come first so the browser parses the main content before the sidebars.

The core idea of the Holy Grail layout is to use the parent container to create two "reserved areas," one on each side.

![WeChat screenshot_20190818135602.png](https://www.yinzhuoei.com/usr/uploads/2019/08/1792369603.png)

Holy Grail layout code (live demo): https://codesandbox.io/embed/red-platform-vtrct
Holy Grail layout summary: the parent box uses padding to reserve space for the sidebars. The center gets a width of 100%, and all three boxes—center, left, and right—are floated. Since the center occupies the full width, the two sidebars get pushed down. We need to move them into the space reserved by the padding. First, give the left box a negative margin-right of 100% to move it into the center of the parent, sharing the first row with the center box. In effect, it covers half of the center box because floating takes it out of normal flow. Then use positioning to move it left by the width of the padding, placing it in the reserved area. For the right box, simply use a negative margin-right equal to the reserved padding.

Double-wing layout (live demo): https://codesandbox.io/embed/elated-kilby-6vqjp
Double-wing layout summary: wrap the center content in a parent element, give that parent a width of 100% and float it, then use margins on the child to reserve space for the other two columns. Move the left and right boxes into position with negative margin-right values.

Comparing the two: personally, I find the Holy Grail layout's DOM cleaner and easier to understand, but its CSS more complicated. The double-wing layout's DOM is less intuitive, but its CSS is easier to follow. Both approaches need an additional div so that the center can float, have a width, and account for the reserved space. Building on the double-wing layout, we can remove that extra div with calc, supported since IE9. Something like calc(100% - 400px) gives us a fluid width, at the cost of compatibility. We can also use border-box or flexbox. See: https://www.jianshu.com/p/81ef7e7094e8

I borrowed a small amount of code and a few ideas from that article for this review, especially its alternative layouts when compatibility isn't a concern.

## How Do You Use HTML5 Offline File Storage, and How Does It Work?

When storage comes up, most frontend developers probably think of HTML5 localStorage or sessionStorage, cookies, or one of the various databases. HTML5 also provides access to local files, so storing things locally is another possibility.

But HTML5 also lets us create a manifest file. Any HTML page that uses it reads a file listing the resources to cache. Those resources remain available even after the network disconnects, provided you've opened the page before and downloaded the files listed in the manifest. Here's a brief look at how that works:

```
<!DOCTYPE HTML>
<html manifest=\"demo.appcache\">

<body>
The content of the document......
</body>

</html>
```

Source: W3C

The recommended extension for this storage file is appcache. We can configure several sections in it, somewhat like Spring Boot configuration in Java.

![WeChat screenshot_20190818225721.png](https://www.yinzhuoei.com/usr/uploads/2019/08/3875776220.png)

This is one of the required sections. Once all the listed files have been cached, the page can run without a network connection!
To summarize the benefits of a manifest:
1.Resources remain available offline.
2.It reduces server requests and bandwidth usage: files aren't downloaded again if they haven't changed.
3.Cached resources load faster!

W3C tutorial on this topic: https://www.w3school.com.cn/html5/html_5_app_cache.asp

## Briefly Explain Your Understanding of BFCs

Let's use this question to explain BFCs. The W3C and MDN explanations can feel vague and difficult, making the concept seem much harder than it really is.
A BFC is essentially an "isolated zone": elements inside and outside don't interfere with one another. Here's an example.

Live demo: https://codesandbox.io/embed/modest-microservice-kn04o
In this code, I only added overflow: auto to the outer box, and the elements inside arrange themselves vertically in the center.

An element establishes a BFC if it meets any one of these conditions:

Its float value isn't none.
Its position value is neither static nor relative.
Its display value is inline-block, table-cell, flex, table-caption, or inline-flex.
Its overflow value isn't visible.

The characteristics of a BFC are:

Internal boxes are placed one after another vertically.
The margins of two adjacent boxes in the same BFC collapse, regardless of direction.
Each element's left outer margin touches the containing block's left edge in a left-to-right layout, even for floats.
A BFC's area doesn't overlap the area of a float.
Floating children are included when calculating a BFC's height.
A BFC is an independent, isolated container on the page. Its children don't affect elements outside it, and vice versa.

For interviews and written tests, understanding these characteristics is enough. In development, you mainly need to know how to debug BFC-related issues and understand the basic concept:
it's a CSS rendering mechanism that acts like a box, isolating its contents from outside elements. That's the key point.

## What Are the Ways to Clear Floats, and Their Pros and Cons?

Floats are already uncommon in everyday development. Flexbox, grid, and normal document flow cover most requirements. The biggest problem floats cause is a collapsed parent height, so that's what we'll focus on fixing.

The cause: a parent contains floated elements, which are outside normal flow, so its height becomes 0.
Solutions:

Take the parent out of normal flow too, so it can "join the kids." (This may affect the entire page layout and makes the code harder to understand: why was the parent removed from normal flow?)

Add a div with clear: both below the floated elements. (An unnecessary element and poor readability; not recommended.)

Use overflow: hidden on the parent to clear the floats. (This may hide content that overflows the parent.)

Use an after pseudo-element on the parent as a clearfix. This is also how Bootstrap handles floats.

If the page rarely changes, fixing the parent box's width and height can also be a good approach, with excellent compatibility.

## Explain Your Understanding of the CSS Box Model

This is very common in interviews. A CSS box has two layers: the outer layer controls its distance from other elements, which we call the margin; the inner layer controls the distance between the border and the content, which we call padding. For the block-level elements we usually use, both the outer and inner layers are block-level. How should we understand that? Take the familiar display: block: its full form is display: block-block, representing the outer and inner layers. The same idea applies to inline-block.

Every box's inner box has properties such as width/height, padding, and border.
Traditionally, an element's occupied width was calculated as width + 2*padding + 2*border. CSS3 introduced box-sizing: border-box, making the final size equal to the specified width and height, with the browser adjusting the contents automatically.

## Explain Your Understanding of JavaScript Scope

JavaScript has global and local scope. The scope inside a script tag is the outermost scope. It can't access variables inside a function's scope, but the function can access the outer scope, unless a closure is involved.
Variables defined inside a function body belong to that function's scope.
ES6 added local scope with let, while const declares constants that can't be reassigned.

About the scope chain:

Let's use a small demo to understand it:

function funcA () {
let a;
function funcB () {
let b;
}
}

When variable a is created inside function a, that function's scope is pushed onto the stack. Function b is then defined inside a, and its scope is also pushed. For a variable in b, lookup first checks b's own scope, then moves upward through the scopes on the stack. If it isn't found even in the top-level scope, it has an undefined value.

## Why Is <!DOCTYPE HTML> Enough for HTML5?

Unlike HTML4, HTML5 isn't an SGML-based markup language. SGML requires a DTD to specify how the browser should render the page, in strict or standards mode. Without one, it falls back to quirks mode.

SGML is a general-purpose markup language framework, and HTML and XML must reference a DTD.

## How Do CSS Sprites Work, and What Are Their Pros and Cons?

These are the sprite sheets we often use at work.
How they work: combine several images or icons into a single image with a tool, then use background-position. Once you know each image's position, you can display it where needed.

Advantages: fewer image requests. Suppose clicking something swaps an image: with a slow network, images might be missing or load late, and sprites can avoid that. They're also great for certain frame-by-frame animations.
Disadvantages: creating sprites takes time, and using them takes time too, especially finding their positions. If you calculate an offset incorrectly, adjacent images can show through. Updating one icon requires downloading the whole sprite sheet again, invalidating its cache.

And under HTTP2, the advantage of reducing request count is largely gone.

## What Is the Difference Between `<script>`, `<script async>`, and `<script defer>`?

A high-frequency interview question:

1. **Standard `<script>`**: When the HTML parser encounters a `<script>` tag, HTML parsing is paused while the script is downloaded and executed immediately. This blocks HTML rendering until the script finishes execution.
2. **`<script async>`**: The script is downloaded asynchronously in parallel with HTML parsing. As soon as the download completes, HTML parsing is paused to execute the script immediately. Because execution timing depends on download completion, execution order across multiple async scripts is not guaranteed.
3. **`<script defer>`**: The script is downloaded asynchronously in parallel with HTML parsing, but its execution is deferred until the entire HTML document has finished parsing (right before the `DOMContentLoaded` event). Deferred scripts execute in the order they appear in the document.

## Explain Your Understanding of GBK vs. UTF-8, and Discuss Reasons for Garbled Characters on a Web Page

A perennial interview question:

- **GBK**: A Chinese character encoding standard designed for Simplified Chinese characters and symbols, using a fixed 2-byte structure for non-ASCII characters.
- **UTF-8**: A variable-width Unicode character encoding capable of representing every character in the Unicode standard (1 to 4 bytes per character). Because of its universal language support, UTF-8 has become the standard encoding across the modern web.

### Reasons for Garbled Characters:
Garbled text occurs whenever there is a mismatch between how text data was encoded and how the browser or software attempts to decode it. For instance:
- The HTML file was saved as GBK, but the HTML document specifies `<meta charset="UTF-8">`.
- The web server sends a response header like `Content-Type: text/html; charset=gbk`, conflicting with `<meta charset="utf-8">`.
- Text copied from a different encoding system was pasted into a file without proper re-encoding.

### How to Prevent and Resolve It:
Ensure consistent character encoding across your entire pipeline: save all source files with UTF-8 encoding, declare `<meta charset="UTF-8">` in the HTML `<head>`, and ensure server HTTP response headers specify `charset=UTF-8`.

## What Is Your Understanding of `z-index`?

`z-index` controls the stacking order of positioned elements along the Z-axis (virtual depth relative to the viewer):

1. **Positioning requirement**: `z-index` only applies to positioned elements (elements where `position` is set to `relative`, `absolute`, `fixed`, or `sticky`) as well as direct children of flex and grid containers.
2. **Stacking contexts**: `z-index` does not operate globally across the entire page; it operates within the element's local **stacking context**. Stacking contexts are formed not only by positioned elements with `z-index`, but also by properties such as `opacity < 1`, CSS `transform`, `filter`, `perspective`, `will-change`, and `isolation: isolate`.
3. **Hierarchical limits**: If element A's parent is stacked below element B's parent, giving element A a massive `z-index: 99999` will never place it above element B.
4. **Layout discipline**: If you frequently find yourself needing arbitrary `z-index` values higher than 2 or 3 in routine layouts, it usually indicates poor DOM structuring or stacking context mismanagement rather than an actual requirement for high numbers.

## Differences Between `bind`, `call`, and `apply`? Implement a Custom `bind`

All three methods are used to set the `this` context for a function invocation:

- **`call(thisArg, arg1, arg2, ...)`**: Invokes the function immediately, binding `this` to `thisArg` and passing arguments individually.
- **`apply(thisArg, [argsArray])`**: Invokes the function immediately, binding `this` to `thisArg` and passing arguments as an array or array-like object.
- **`bind(thisArg, arg1, arg2, ...)`**: Does **not** invoke the function immediately. Instead, it returns a new bound function with `this` permanently set to `thisArg`, allowing parameters to be partially applied (currying).

### Custom `bind` Implementation:

```javascript
Function.prototype.myBind = function(context, ...args) {
  const fn = this;
  if (typeof fn !== 'function') {
    throw new TypeError('Function.prototype.bind - target must be callable');
  }

  function boundFunction(...innerArgs) {
    // When invoked with the 'new' operator, use the newly created instance as this
    const isNew = this instanceof boundFunction;
    return fn.apply(isNew ? this : context, [...args, ...innerArgs]);
  }

  // Preserve the prototype chain if used as a constructor
  if (fn.prototype) {
    boundFunction.prototype = Object.create(fn.prototype);
  }

  return boundFunction;
};
```

## What Is Your Understanding of `arguments`? Is It an Array?

`arguments` is **not** an array; it is an **array-like object** accessible inside non-arrow functions.

1. It has integer keys (`0`, `1`, `2`, ...) representing positional arguments and a `.length` property.

## What Is the Difference Between `rgba()` and `opacity` for Transparency?

1. **Inheritance & Scope**:
   - `opacity` affects the entire element and **all child elements inside it**. Children inherit the semi-transparency; setting `opacity: 1` on a child cannot undo the parent's opacity.
   - `rgba(r, g, b, a)` applies transparency **only to the specific property** it is assigned to (such as `background-color` or `border-color`). Child elements and text remain completely opaque unless styled separately.
2. **Property vs. Value**:
   - `opacity` is an independent CSS property accepting a number from `0` to `1`.
   - `rgba()` is a CSS functional color notation that produces a color value for any property expecting `<color>`.
3. Note that `transparent` is a CSS color keyword functionally equivalent to `rgba(0, 0, 0, 0)`.

## Explain This Code Snippet: `[].forEach.call($$("*"), function(a){ a.style.outline = "1px solid #" + (~~(Math.random() * (1 << 24))).toString(16); })`

This is a well-known CSS debugging one-liner runnable in the browser DevTools console:

### Step-by-Step Breakdown:
1. `$$("*")`: In browser DevTools consoles, `$$` is a convenience shorthand for `document.querySelectorAll("*")`, selecting every DOM element on the page.
2. `[].forEach.call(...)`: Borrows `Array.prototype.forEach` to iterate over the resulting `NodeList`.
3. `a.style.outline = ...`: Applies an `outline` to each DOM node `a`. (`outline` is used instead of `border` because `outline` does not take up box-model space or cause layout shifts).
4. `(1 << 24)`: Bitwise shift computing `2^24 = 16,777,216`, which is the total number of colors in 24-bit RGB space (`0x000000` to `0xFFFFFF`).
5. `Math.random() * (1 << 24)`: Generates a random floating-point number between `0` and `16777216`.
6. `~~(...)`: Double bitwise NOT operator, truncating fractional numbers quickly (equivalent to `Math.floor()`).
7. `.toString(16)`: Converts the resulting integer into a hexadecimal color string.

**Outcome**: It outlines every DOM element on the page in a random color, making it easy to visualize layout boxes, nesting depths, and overflow issues during development.

## What Happens When You Enter a URL in the Browser Until the Page Renders?

A quintessential web fundamentals interview question:

1. **URL Parsing**: The browser parses the scheme (`http`/`https`), host name, port, path, query parameters, and fragment identifier.
2. **DNS Resolution**:
   - Looks up IP via local browser cache -> OS cache (`/etc/hosts`) -> Router cache -> Local ISP recursive resolver.
   - If not cached, the resolver queries Root -> TLD (`.com`) -> Authoritative DNS servers to obtain the server's IP address.
3. **TCP Connection & TLS Handshake**:
   - Performs TCP Three-Way Handshake (`SYN` -> `SYN-ACK` -> `ACK`).
   - If HTTPS, initiates the TLS handshake: certificate validation, cipher suite negotiation, and session key exchange.
4. **HTTP Request & Response**:
   - The browser constructs and sends the HTTP request headers and payload.
   - The server processes the request and streams back the HTTP response (`200 OK`, response headers, HTML payload).
5. **Browser Rendering Pipeline**:
   - **DOM Tree**: The HTML parser converts raw bytes into characters, tokens, nodes, and finally builds the DOM tree.
   - **CSSOM Tree**: The CSS parser evaluates styles and builds the CSSOM tree.
   - **Render Tree**: Combines DOM and CSSOM trees, omitting non-rendered elements (`<head>`, `display: none`).
   - **Layout (Reflow)**: Computes the precise geometry, coordinates, and dimensions of each node on the screen.
   - **Paint (Repaint)**: Paints colors, borders, text, and shadows into drawing layers.
   - **Composite**: The GPU composites multiple layers into the final screen buffer.
6. **Resource Loading & Script Execution**:
   - Encounters external resources (`<img>`, `<link>`, `<script>`). Parser-blocking scripts pause HTML parsing unless tagged with `async` or `defer`.
7. **Connection Teardown**:
   - TCP Four-Way Handshake terminates the connection, or reuses it via HTTP `Keep-Alive`.

## What Is Web Accessibility (WAI / WCAG)? How Do You Implement It in Development?

Web Accessibility (WAI / WCAG) ensures that websites and digital products are fully usable by people with disabilities (visual, auditory, motor, or cognitive impairments), as well as users relying on assistive technologies like screen readers or switch devices.

### Development Best Practices:
1. **Semantic HTML**: Always favor native HTML elements (`<header>`, `<nav>`, `<main>`, `<article>`, `<button>`, `<dialog>`) over generic `<div>` click listeners. Native elements provide built-in keyboard navigation, focus management, and screen-reader accessibility roles for free.
2. **Meaningful Alt Text**: Always provide descriptive `alt` attributes on `<img>` tags (or `alt=""` for purely decorative graphics so screen readers ignore them).
3. **Form Associations**: Explicitly tie `<label>` elements to `<input>` fields using matching `for` and `id` attributes.
4. **Prudent ARIA Usage**: Use WAI-ARIA attributes (`aria-label`, `aria-expanded`, `aria-hidden`, `role`) for custom dynamic widgets, following the first rule of ARIA: *"Do not use ARIA if a native HTML element can do the job."*
5. **Keyboard Navigability**: Ensure all interactive controls are reachable via `Tab` with clearly visible focus rings (`:focus-visible`).
6. **Color Contrast**: Maintain minimum color contrast ratios (at least 4.5:1 for normal text and 3:1 for large text according to WCAG AA standards).

## Describe the Specificity Calculation Rules in CSS

CSS specificity determines which declaration takes precedence when multiple rules match the same element:

### Specificity Hierarchy (from highest to lowest):
1. `!important` (overrides all normal cascade specificity)
2. Inline styles: `style="..."` (Score: 1, 0, 0, 0)
3. IDs: `#nav`, `#user-profile` (Score: 0, 1, 0, 0)
4. Classes, attributes, and pseudo-classes: `.btn`, `[type="text"]`, `:hover`, `:nth-child(2)` (Score: 0, 0, 1, 0)
5. Elements and pseudo-elements: `div`, `span`, `p`, `::before`, `::after` (Score: 0, 0, 0, 1)
6. Universal selector (`*`), combinators (`+`, `>`, `~`, space), and `:where()` contribute 0 specificity (0, 0, 0, 0).

### Classic CSS Specificity Quiz:

```html
<div class="red blue">123</div>
<div class="blue red">123</div>
```

```css
.red {
  color: red;
}

.blue {
  color: blue;
}
```

**Question**: What color will the text "123" render in each div?

**Answer**: Both divs render in **blue**! CSS specificity is completely unaffected by the order of class names in the HTML `class` attribute. Because `.red` and `.blue` have identical specificity (0, 0, 1, 0), the CSS cascade resolves ties by source order: `.blue` is written after `.red` in the CSS stylesheet, so `.blue` wins.

## What Problem Do CAPTCHAs Solve on the Web? What Types of CAPTCHAs Are You Familiar With?

### Problems CAPTCHAs Solve:
CAPTCHA (*Completely Automated Public Turing test to tell Computers and Humans Apart*) protects web services from automated bots and malicious scripts:
- Preventing brute-force password guessing and credential stuffing
- Blocking automated spam in comments, reviews, and sign-up forms
- Mitigating scalper bots on ticketing and flash-sale platforms
- Thwarting distributed Denial of Service (DoS) attacks on expensive computation endpoints

### Common Types of CAPTCHAs:
1. **Text/Distorted Image CAPTCHAs**: Distorted letters and numbers overlaid with noise lines.
2. **Slider / Puzzle CAPTCHAs**: Users drag a slider to fit a puzzle piece into a missing slot.
3. **Click / Sequence Verification**: Users click designated characters or objects in a specified order.
4. **Behavioral Risk Analysis**: Invisible verification systems (such as Google reCAPTCHA v3 or Cloudflare Turnstile) that score risk based on cursor movement and interaction cadence without interrupting the user.
5. **SMS / Voice OTP**: Out-of-band one-time verification codes sent to authenticated phone numbers.

## Describe Image Formats You Know and Their Use Cases

1. **JPEG / JPG**:
   - Lossy compression, 24-bit color depth, small file size.
   - Ideal for photographic images with continuous gradients and colors. Does not support transparency.
2. **PNG**:
   - Lossless compression, supports full alpha-channel transparency and crisp edges.
   - Best for UI icons, screenshots, logos, and images requiring transparency.
3. **GIF**:
   - 8-bit palette (maximum 256 colors), supports simple frame animation and binary transparency.
   - Used for lightweight short animations and memes.
4. **SVG**:
   - XML-based vector graphics, infinitely scalable without resolution loss or pixelation.
   - Can be styled with CSS and manipulated via JavaScript. Best for UI icons, logos, and vector illustrations.
5. **WebP / AVIF**:
   - Next-generation formats providing significantly better compression (both lossy and lossless) than JPEG and PNG at equivalent or superior quality. Supports transparency and animation; recommended as modern web defaults.

## Write a Method to Determine Whether a String Is a Palindrome

A palindrome reads the same backwards as forwards (e.g., `"racecar"`, `"level"`, `"A man, a plan, a canal: Panama"`).

```javascript
// Method 1: Array reverse
function isPalindrome(str) {
  const cleanStr = str.replace(/[^a-zA-Z0-9]/g, '').toLowerCase();
  return cleanStr === cleanStr.split('').reverse().join('');
}

// Method 2: Two-pointer approach (O(n) time, O(1) space)
function isPalindromeTwoPointer(str) {
  let left = 0;
  let right = str.length - 1;
  while (left < right) {
    if (str[left] !== str[right]) {
      return false;
    }
    left++;
    right--;
  }
  return true;
}
```
