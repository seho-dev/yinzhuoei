# Prerequisites

- [important] Be good at adding content to template / example so that SKILL.md is always clean!
- When a user selects a skill for a scenario, they need to read the documentation and context and follow the best practices for skills to create a skill for the corresponding scenario

- Output path: .claude/skills\

# Create rules

## 1. Naming Conventions

### Skill Name Requirements

- **Format**: Use only lowercase letters, numbers, and hyphens
- **Length**: Maximum 64 characters
- **Example**:

```yaml
name: pdf-processor # ✅ Correct

name: PDF_Processor # ❌ Incorrect: Contains uppercase letters and underscores

name: pdf-processor-v2 # ✅ Correct
```

### Description Field Conventions

- **Length**: Maximum 1024 characters
- **Content**: Must contain two key elements

1. **Function Description**: What the skill does
2. **Trigger Conditions**: When to use the skill

**Description Example Comparison:**

```yaml
# ❌ Too vague

description: Helps process documents

# ✅ Precise description

description: Extracts PDF text and tables, populates forms, merges documents. Use when processing PDF files or when users request PDF, form, or document extraction.

# ✅ Contains trigger keywords

description: Analyzes code quality, detects security issues, and suggests optimization solutions. Automatically triggered when users request code review, security checks, or performance optimization.

``

## 2. Best Practices for Skill Structure

### Single File Skills (Simple Scenarios)

```markdown

---
name: safe-file-reader

description: Read-only file access, no modification. Used when read-only file access is required.

allowed-tools: Read, Grep, Glob

---

# Safe File Reader

## Instructions

1. Use Read to view file content

2. Use Grep to search within a file

3. Use Glob to find files by pattern

## Examples View configuration file:
```

### Multi-file skills (complex scenarios)

```
code-analyzer/

├── SKILL.md # Main skill file

├── examples/ # Example collection

│ ├── security-scan.md

│ └── performance-check.md

├── templates/ # Template file

│ ├── security-report.md

│ └── performance-report.md

└── scripts/ # Auxiliary scripts

└── analyze.py
```

**Example of main file reference:**

```markdown
## Detailed Usage

Refer to [examples/security-scan.md](examples/security-scan.md)

## Generating Reports

Generate a report using a template:

```bash
python scripts/analyze.py --template templates/security-report.md
```

```
## 3. Best Practices for Access Control

### Principle of Least Privilege

```yaml

# Read-only skills

allowed-tools: Read, Grep, Glob

# Data analysis skills (do not modify files)

allowed-tools: Read, Grep, Bash, Python

# Document processing skills (can be modified)

allowed-tools: Read, Write, Convert, Merge
```

### Example of Hierarchical Permissions

```markdown
---
name: code-reviewer
description: Analyze code quality and detect security issues. Used when users request code reviews.

allowed-tools: Read, Grep, Bash

---

# Code Reviewer

## Security Check

1. Use Grep to search for sensitive information patterns

2. Run static analysis tools

3. Generate a security report

## Permission Explanation

- Read: Read source code files

- Grep: Search for specific patterns

- Bash: Run analysis tools (without modifying files)
```

## 6. Common Error Avoidance

### ❌ Error Examples

```yaml
# Description too vague

description: Help process files

# Name does not conform to specifications

name: File_Helper

# Missing trigger condition

description: Analyze Code Quality
```

### ✅ Correct Example

```yaml
# Precise Description + Triggering Conditions

description: Extracts text and tables from PDF and merges documents. Used when processing PDF files or when a user mentions a PDF.

# Conforms to Naming Conventions

name: pdf-processor

# Contains Triggering Keywords

description: Analyzes code quality and detects security issues. Automatically triggered when a user requests code review or security checks.
```

## 7. Performance Optimization Recommendations

### File Organization Optimization

```skill-name/
├── SKILL.md # < 5KB, core logic

├── examples/ # Load on demand

├── templates/ # Load on demand

└── scripts/ # Execute on demand
```

### Context Management

- Place detailed documentation in a separate file
- Use link references: `[detailed description](reference.md)`
- Avoid including large amounts of sample code in SKILL.md
